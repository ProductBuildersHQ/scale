## [v0.2.0] - 2026-08-08 ([`8669930`](https://github.com/ProductBuildersHQ/scale/commit/8669930))

### Highlights

- Platform Adoption domain: a fourth reference domain measuring adoption and leverage of internal platform libraries across the organization's Go repositories via dependency analysis
- ReportIR: a format-agnostic report intermediate representation with a JSON renderer and HTMLFromIR, so a report can be computed once and cached, served as JSON, or rendered in multiple formats
- MkDocs documentation site published at productbuildershq.com/scale

### Added

- Platform Adoption domain (catalog/domains/platform.json): library existence (Standards), per-library adoption rates (Consumption/adoption), and reuse leverage (Leverage); the reference catalog now seeds four domains (api, observability, platform, security) ([`72df817`](https://github.com/ProductBuildersHQ/scale/commit/72df817))
- ReportIR intermediate representation with BuildIR, a JSON renderer, and HTMLFromIR, carrying all computed report data (aspects, movers, domains, capabilities, coverage) without the source Framework or Assessment ([`7658694`](https://github.com/ProductBuildersHQ/scale/commit/7658694))

## [v0.1.0] - 2026-07-25 ([`0230eb9`](https://github.com/ProductBuildersHQ/scale/commit/0230eb9))

### Highlights

- Machine-readable framework for telling the platform story: how engineering best practices are Standardized, Consumed, Automated, Leveraged, and made Effective

### Added

- Core SCALE types: Framework, Domain, Capability, Metric, Assessment, NarrativeBlock ([`d32e575`](https://github.com/ProductBuildersHQ/scale/commit/d32e575))

- Weakest-link maturity semantics: capability maturity = min(metric rungs), domain maturity = min(capability rungs) ([`d48d3dd`](https://github.com/ProductBuildersHQ/scale/commit/d48d3dd))
- ComputeRollup for attainment calculation with domain aspect scores as plain means ([`ab7d45f`](https://github.com/ProductBuildersHQ/scale/commit/ab7d45f))
